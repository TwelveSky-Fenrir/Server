# Fix-forward for a fail-closed regression: game.Characters.PreviousTribe (see Tables/game/Characters.sql) is
# NOT NULL DEFAULT 0, which applies retroactively to every row that already existed at the moment its ALTER
# TABLE originally ran -- i.e. any character created before PreviousTribe was introduced. EnterWorldService.
# HandleAsync aborts the session outright (Server/ts25zone/S04_MyWork02.cpp:880-901's self-consistency check:
# a main-faction Tribe 0-2 requires PreviousTribe == Tribe) whenever the two fields disagree. Combined, every
# already-created character with Tribe = 1 or Tribe = 2 -- the large majority of any pre-existing population --
# would silently receive PreviousTribe = 0 from the DEFAULT and then be permanently unable to enter the world
# afterward. This is a fail-closed denial-of-service against legitimate, already-existing accounts, not
# anything a player did -- backfills PreviousTribe = Tribe for every main-faction row that hasn't already been
# set to a non-default value. Kept as a standalone migration (not merged into the table's own creation script)
# since it is a one-time DATA correction against pre-existing rows, not a schema shape change -- a fresh
# database has no rows for it to touch.
Migrations/019_character_previous_tribe_backfill.sql
